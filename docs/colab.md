# aether — первый Colab preflight

Notebook подготовлен: `notebooks/aether_colab.ipynb`. Локально проверены JSON,
компиляция и отсутствие outputs; ячейки Colab здесь не исполнялись. A16 остаётся
частично выполненной до успешного запуска в свежей удалённой среде.

## Что сделать пользователю

1. Открыть notebook через загрузку файла в Colab. Выбрать удалённый управляемый
   GPU runtime платного аккаунта; local runtime не подключать. Для BF16-кандидата
   ориентир 24+ ГБ GPU, но сначала требуется измерение фактически выделенной памяти.
2. В настройках оставить `RUN_TRAINING=False`, `BUDGET_UNITS=500`, путь Drive
   `/content/drive/MyDrive/aether`. Задать уникальный `RUN_ID`, например
   `english-demo-preflight-001`. Подтвердить `CONFIRM_REMOTE_PAID_COLAB=True`
   только после проверки своего подключения и платного аккаунта в UI.
3. Скопировать строку из `dist/aether-source.sha256` в `SOURCE_SHA256`.
   В ячейке загрузки выбрать `dist/aether-source.zip`. Архив включает текущие
   незакоммиченные исходники; git commit не выдумывается. Повторная сборка:
   `uv run --locked python scripts/build_colab_bundle.py`.
4. Выполнить ячейки по порядку. Установятся uv 0.12.13, Python 3.12.14 и только
   основные зависимости из lock-файла. Процесс пакета вызовет validation-only,
   соберёт RAM/диск/`nvidia-smi`, после авторизации Drive сохранит `preflight.json`
   в новый `runs/<RUN_ID>/`. Существующий run не перезаписывается.
5. Передать полученный `preflight.json` для выбора модельных зависимостей и
   допустимых размеров. Проверить расход юнитов в интерфейсе и отключить GPU
   runtime после получения отчёта, чтобы не оставлять платную среду простаивать.

Notebook не скачивает веса, не делает forward, не создаёт optimizer и не обучает.
Признаки Colab и подтверждение пользователя записываются как наблюдения, не как
доказательство тарифа или управляемой инфраструктуры. Обучающий gate закрыт.
500 юнитов — лимит стадии, не оценка числа часов и не автоматически контролируемый
API-бюджет. Фактический тариф/остаток проверяет пользователь в интерфейсе Colab.

## Выбор комплекта

Исследован опубликованный BF16-комплект для английского голосового диалога:
голосовая модель около 15.4 ГБ, начальный кодек около 385 МБ и текстовый токенизатор
около 553 КБ. Кандидат совпадает по основному контракту 24 кГц/12.5 Гц, восьми
активным книгам, текстовому словарю и задержкам. Ссылки на первичные источники
предоставлены в разговоре; внешние имена не внесены в проектные файлы.
Это рекомендация, не результат загрузки и проверки state_dict. До интеграции
нужны точные revision/хеши, полный архитектурный конфиг и соблюдение требований
атрибуции источника весов. Ребрендинг проекта не меняет происхождение артефактов.

## Хранение checkpoint

`aether.storage` создаёт новые run/checkpoint-каталоги, копирует файлы, сверяет
размеры/SHA-256, затем публикует `COMPLETE`, связанный с хешем манифеста.
`resumable_checkpoints` возвращает только полностью проверенные каталоги;
повреждённые и незавершённые копии игнорируются. Имена не переиспользуются.
Локально проверены disk-full, порча файла/маркера, лишний файл и запрет перезаписи.
Drive/FUSE и восстановление после удаления реального runtime ещё не проверены;
A17 открыта. Это файловый механизм, не восстановление состояния тренера.

## Готовность к обучению

Её пока нет: реальная модель, строгая загрузка весов, данные, baseline и тренер
не реализованы/не проверены. Секции baseline/pilot/resume/train/evaluate/export
в notebook явно сообщают блокировки и не имитируют работу. После их готовности
будет отдельное уведомление с точными параметрами; preflight этого не заменяет.
